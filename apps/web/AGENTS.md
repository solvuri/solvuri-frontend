## Solvuri Web — project notes

- Static marketing site — no auth, no data layer (`@repo/data` isn't a dependency here), no client-side state beyond simple component state (e.g. the Navbar's mobile-menu toggle). **One exception**: `app/contact/ContactForm.tsx`'s "Super License" reason now makes a real API call (see below) — the first real backend call this app has ever made. `lib/api.ts` (`webApi = createApiClient(process.env.NEXT_PUBLIC_API_URL!)`) exists for exactly this, mirroring the identical pattern in `apps/admin-portal`/`apps/clearack`/`apps/pos`'s own `lib/api.ts`. `.env.local`/`.env.example` point at the real test backend (`https://backend-api-test.solvuri.com`) — previously left as an unused placeholder (`api.solvuri.com/v1`) since nothing called it.
- **`/contact` wires the real, anonymous `POST /api/tenant-requests/request-license` endpoint** when "Super License" is selected as the reason — `@repo/api-client`'s new `tenantRequests.ts` (`submitTenantRequest`). The real `CreateTenantRequestDto`'s fields (`firstName`/`middleName`/`lastName`/`brandName`/`email`/`phoneNumber`/`businessDescription`/`requestedSystems`) don't map onto the form's original generic fields (`name`/`company`/`email`/`message`), so selecting "Super License" swaps in a distinct field set instead of trying to force-fit one form shape to two different backends. `requestedSystems` is a free-text string server-side; the UI collects it as Clearack/POS checkboxes and joins the selection with `", "` before submitting — not confirmed via probing that the backend expects exactly that format, since the only documented example is a single value. The other three reasons (General/Support/Partnership) have no backend endpoint at all and still just simulate success after a delay, same as before — don't assume they're wired too.
- Shared design tokens (background/surface/foreground/border/ring/radius/fonts) come from `packages/ui/src/styles/solvuri-theme.css`'s vocabulary, imported by `app/globals.css`. Use the token classes (`bg-background`, `text-primary`, etc.) rather than hardcoded hex.
- `components/navigation/Navbar.tsx`/`Footer.tsx` are thin wrappers around `@repo/ui`'s shared `Navbar`/`Footer` (`variant="floating"`) — this app's actual chrome markup lives in `packages/ui/src/navbar.tsx`/`footer.tsx`'s `FloatingNavbar`/`FloatingFooter` branches. Pass content via props; don't add markup back into this app's local wrapper files.
- This is the only app with `--max-warnings 0` enforced from the start; `check-types` also runs `next typegen` before `tsc --noEmit`.
